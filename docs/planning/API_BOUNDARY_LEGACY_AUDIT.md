# API 边界当前状态

本文档只描述当前接口边界结论，不再保留历史审计过程或分批清理计划。

## 1. 当前四层模型

RewrZ 当前接口边界按四层划分：

- 前台公共 API：`/api/v1/...`
- 前台登录态 API：固定公共路径，但继续要求登录态或 CSRF
- 外部集成 API：`/api/external/v1/...`
- 后台管理 API：`{ADMIN_PATH}/api/v1/...`

## 2. 当前稳定结论

### 2.1 前台公共 API

适合继续保持固定公共路径的能力：

- 认证状态
- 搜索
- RSS / SEO / 主题变量读取
- 评论表单与评论嵌入
- 前台互动汇总与公共只读能力

### 2.2 前台登录态 API

适合继续保持固定公共路径，但必须要求登录态或 CSRF 的能力：

- 前台快捷发帖
- 前台快捷媒体上传
- 头像自助管理

### 2.3 外部集成 API

对外系统统一走：

- `/api/external/v1/posts`
- `/api/external/v1/pages`
- `/api/external/v1/categories`
- `/api/external/v1/tags`
- `/api/external/v1/media`

外部 API 只走 API Key，不复用后台 Cookie 与后台路径。

### 2.4 后台管理 API

以下能力属于后台管理面：

- 用户管理
- 仪表盘
- 设置
- 媒体管理
- API Key 管理
- 评论设置与安全中心
- 主题后台配置

这些能力的主路径应稳定收敛到：

- `{ADMIN_PATH}/api/v1/...`

## 3. 当前兼容策略

- 新能力默认直接落在最终目标路径
- 不再新增新的旧 `/api/...` 兼容层
- 已存在的旧 `/api/...` 别名只在仍有真实调用价值时保留
- 文档中不再把旧别名描述为长期稳定接口面

## 4. 使用规则

- 设计新接口时，必须先判断其属于哪一层
- 只要语义属于后台管理，就不要因为“实现方便”放到公共路径
- 只要语义属于外部系统，就不要复用后台管理 API
