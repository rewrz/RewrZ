# RewrZ 路线图

说明：路线图不代表发布日期承诺，而是研发方向与优先级参考。

## 1. 已完成（近期）

- [x] 关键后台写接口补齐鉴权 + CSRF
- [x] 媒体上传改为流式写入，避免整文件读内存
- [x] 备份包导入增加安全解包校验
- [x] 配置层强化（弱密钥防护、Cookie/Session 安全选项）
- [x] 文档中枢初版（架构/模型/API/排障/部署）

## 2. 进行中（高优先级）

- [ ] API 分层再收敛（后台管理接口与公共接口边界更清晰）
- [ ] 文档与测试持续补齐（新功能必须带回归测试）
- [ ] 线上可观测性增强（错误定位、关键操作审计）

## 3. 计划中（功能方向）

### 3.1 AI 对接能力（探索）
- [ ] 内容辅助创作：摘要、标题建议、标签建议
- [ ] 评论辅助治理：可疑评论评分与人工复核队列
- [ ] 内容检索增强：语义搜索/相关内容召回

落地前提：
- AI 能力默认可开关，且有明确成本控制
- 不破坏现有内容模型约束（`post_type` 与 `formats`）
- 敏感数据处理要有明确边界与日志策略

### 3.2 联邦化/去中心化能力（探索）
- [ ] 调研 ActivityPub 兼容层（类似 Misskey/Mastodon 联邦协议思路）
- [ ] 设计“对外可见实体映射”：作者、文章、评论、互动
- [ ] 设计实例间同步与信任边界（签名、黑名单、速率限制）

落地前提：
- 联邦能力作为可选模块，不强耦合核心发布链路
- 保持本地实例可独立运行（单机模式始终可用）
- 先做只读联邦，再评估写入联邦能力

## 4. 暂缓项

- [ ] 大规模插件市场化（当前不作为优先方向）
- [ ] 过度复杂的主题编排系统（避免再次走向重型 CMS）

## 5. 版本演进原则

1. 先收敛模型，再扩展能力
2. 先补测试，再扩大接口面
3. 先保证可维护，再追求功能堆叠
