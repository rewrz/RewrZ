# RewrZ 路线图

本文档只保留当前有效的产品与工程方向，不再记录已经完成的长清单、阶段性审计过程或中间推进笔记。

## 1. 当前状态

截至当前代码状态，以下方向已完成收敛：

- API 已明确分为四层：
  - 前台公共 API：`/api/v1/...`
  - 前台登录态 API：固定公共路径，但继续要求登录态或 CSRF
  - 外部集成 API：`/api/external/v1/...`
  - 后台管理 API：`{ADMIN_PATH}/api/v1/...`
- 后台动态路由已集中到 `rewrz/api/admin_routes.py`
- 外部 API 首期能力已落地：
  - 文章、页面、分类、标签、媒体上传
  - API Key 鉴权与后台管理
- 后台用户管理已具备完整基础能力：
  - 新增用户
  - 启停
  - 角色调整
  - 密码重置
  - 强制退出
- 登录前忘记密码闭环已落地：
  - 登录页入口
  - 找回密码页
  - 一次性重置链接
  - 重置成功后旧登录态失效
  - 开发环境调试投递日志
- 历史 `post_type` 运行时归一化已移除，改为迁移/一次性修复策略
- 已删除明显无效的遗留目录与备份 CSS 目录

## 2. 当前优先级

以下事项仍然值得继续推进，但不再按旧的逐项勾选表维护：

### 2.1 文档持续收敛

- 继续将文档从“过程记录”压缩为“当前状态说明”
- 涉及接口、测试、部署、安全边界变化时，同步更新对应主文档

### 2.2 测试基线持续维护

- 保持关键能力具备专项回归测试：
  - 外部 API
  - 后台用户管理
  - 登录 / 登出 / 忘记密码
  - 权限与 CSRF
- 如需引用“全量测试耗时”，必须重新实测后再写入文档

### 2.3 性能与运维可观测性

- 保持仪表盘健康检查、公开聚合页、媒体归档页等热点路径有明确基线
- 继续优先修正“高成本 Python 侧聚合”与“重复扫描文件系统”类问题

### 2.4 接口边界继续减债

- 逐步减少仅为历史调用保留的旧 `/api/...` 别名
- 不新增新的运行时兼容层
- 所有新能力默认直接落在最终目标路径，不再新增“过渡路径”

## 3. 不再作为默认目标的方向

以下事项当前不作为默认研发方向，除非出现新的明确需求：

- 运行时历史兼容分支扩张
- 复杂 RBAC / 多租户权限系统
- 面向 APP 的独立 BFF 必选层
- 继续扩展旧 `/api/...` 镜像别名

## 4. 更新规则

- 本文档只写“当前状态 + 仍然有效的下一步方向”
- 已完成事项并入“当前状态”，不再保留长篇执行过程
- 需要过程证据时，写入 `docs/testing/` 或对应专项文档，不在路线图里堆积历史过程
